## 0. 왜 lite인가 (문제 정의)

골든 1본 = **1세션 + 서브에이전트 ~34회 + 카드 중앙값 53.5장/산문 24,250자**(V-113 실측). 2,651 상장사 확장은 산술적으로 불가능하다.
그러나 **처음 보는 사람에게 필요한 건 2,651가지 서사가 아니라, 한 번 제대로 배운 표준 + 그 표준과의 차이**다.

→ **3티어 제품 구조**
| 티어 | 대상 | 산출 | 생산 |
|---|---|---|---|
| **골든(표준)** | 20 클러스터 대표 1사 | 풀 은하수 5존·딥다이브 53장 — *튜토리얼* | 1본 1세션 (기존 MILKYWAY 파이프라인) |
| **lite(델타)** | 같은 클러스터의 나머지 | 표준 대비 차이 6단 뷰 | 코드 규칙 + 카드 2~4장만 LLM |
| **scope-out** | 금융·지주·리츠·스팩·우선주 | 미제공 (계정 체계 상이) | — |

## 1. EQS 탭과의 차별 (설계 제1 게이트)

lite가 "요약 지표 나열"이 되면 **탭③ EQS와 중복**된다. EQS(firm.html)가 이미 하는 것:

> EQS 종합점수·등급 / 5개 모듈(M1 OCF÷영업이익, M2 매출채권vs매출, M3 부채비율 백분위, M4 이익률) / 수익성 지표(GPM·OPM·NPM·ROE·ROA) / **KSIC 동종 n개사 평균 대비 바차트** / 매출·OCF·순이익 시계열 / 손익·재무상태·현금흐름 3표 / 주목 포인트(severity) / 쉬운 말 3줄 요약

| 축 | 탭③ EQS | 탭② 은하수 lite |
|---|---|---|
| 비교 대상 | 동종업계 **통계**(평균·백분위) | 학습한 **표준 기업의 항로**(서사) |
| 단위 | 비율·점수 — *상태 평가* | 현금의 **경로·사건·연도** — *5년 여정* |
| 던지는 질문 | "잘하나 못하나" | "표준에서 배운 그 장면이 이 회사에선 어떻게 다른가" |
| 근거 | 정형계정 통계 | 항로 지도 + 사업보고서 **주석 원문** |

**lite 금지 목록**: 점수·등급·백분위 / ROE·ROA·마진 등 비율 나열 카드 / 업계 평균 대비 바차트 / 손익·재무상태·현금흐름 표 재현.
→ 필요하면 에필로그에서 **"지표로 평가된 성적은 EQS 재무분석 탭에서"** 크로스링크로 위임한다.

## 4. 8상 패턴 배지 — (OCF, ICF, FIN) 부호 3튜플

교과서 분류에 **초심자용 이름**을 붙인다. 배지는 최근 연도, 본문은 5년 변화 경로를 서술.

**전 상장사 커버리지 실측 (2026-08-11, firm JSON 2,743사)**: CF 3종 보유 = **2,603사 분류 가능(94.9%)**, CF 전무 140사(분류 불가 → 패턴·현금 카드 skip). 분포: 자가발전형 33.9% · 확장투자형 22.4% · 외부수혈형 16.3% · 정리형 10.7% · 구조조정형 6.5% · 버티기형 5.3% · 소진형 3.5% · 비축형 1.5% — **8상 전부 실존**.
**한계 2가지 (정직하게 명시)**: ① 부호만 보므로 **크기를 말하지 않는다** — 규모 서술은 카드가 담당. ② **근소값 민감** — 세 계정 중 하나가 매출 1% 미만인 회사가 21.2%로, 부호가 쉽게 뒤집힌다 → 빌더가 `pattern.edge` 플래그를 세우고 화면에 "일부 현금흐름이 0에 가까워 다음 결산에 유형이 바뀔 수 있어요"를 표시한다. 즉 8상은 **전 상장사를 빠짐없이 분류하는 국면 라벨**이되, 설명의 본체는 카드다.

| 부호 | 이름 | 한 줄 뜻 |
|---|---|---|
| `+ − −` | **자가발전형** | 벌어서 투자하고 빚도 갚아요 (성숙 우량의 전형) |
| `+ − +` | **확장투자형** | 벌면서도 외부 자금을 더 당겨 투자해요 |
| `+ + −` | **정리형** | 벌고 자산도 팔아 빚을 갚아요 |
| `+ + +` | **비축형** | 벌고 팔고 빌리고 — 현금을 쌓는 국면이에요 |
| `− − +` | **외부수혈형** | 영업에선 못 벌고 조달로 버티며 투자해요 |
| `− + +` | **버티기형** | 영업 적자를 자산 매각과 조달로 메워요 |
| `− + −` | **구조조정형** | 자산을 팔아 빚을 갚는 국면이에요 |
| `− − −` | **소진형** | 벌지 못하는데 투자와 상환이 겹쳐 현금이 빠르게 줄어요 |

## 5. 이중 항로 지도 (차이를 즉시 인식시키는 장치)

1. **정규화 오버레이** — 이 회사 항로 위에 표준 항로를 **매출=100 정규화 고스트**로 겹친다. 규모(11조 vs 334조)가 30배 달라도 *모양* 비교가 성립한다. 토글로 표준 on/off.
2. **델타 하이라이트** — 정규화 격차가 임계 이상인 마디에 자동 배지. 색은 DESIGN.md §2 의미색 고정(mint=손익, cyan=현금, coral=유출, steel=잔액, gold=자본) — 델타의 방향은 배지 문구와 화살표로, **색을 의미 밖으로 쓰지 않는다**.
3. **양방향 앵커** — 지도 마디 클릭 → 해당 델타 카드로 스크롤 / 카드 호버 → 지도 마디 하이라이트.
4. **표준 딥링크 = 딥다이브 직결 (UX-041)** — 카드마다 "표준의 이 항목 딥다이브 보기" → `galaxy.html?ticker=<표준>&focus=dive:<key>`로 **그 항목 딥다이브를 바로 고정(pin)** + 해당 행 스크롤. 착지 키는 빌더가 골든 dives의 `row` 값으로 해석(is-opincome·cf-fin·bs-cash·is-cogs…), 주석 카드는 n7·n12·ppe 등으로 직결. 존 스크롤(`focus=zone<X>`)은 폴백. 골든 쪽엔 focus 수신만 **추가**(기존 렌더 경로 무수정).

## 6. 델타 카드 — 5~6장 (직관 서술, 비유 최소화)

**멘트 규격 (3문장)**: ① 표준에서는 A였어요 → ② 이 회사는 B예요 → ③ 그래서 C예요.
**문체 (UX-041, 리더 확정)**: 경어체(`~예요/~해요`)·격식체 금지·숫자 `[브래킷]`은 골든과 동일하되, **골짜기·영업 존·강줄기·저수지·항로 같은 은유를 카드 본문에 쓰지 않는다** — 골든은 은유가 강·매듭 시각화와 결합해 성립하지만, lite는 그 시각화가 없어 은유가 이해를 가린다. 용어는 그 자리에서 직관 풀이("재무활동 현금이 (+)라는 건, 갚은 돈보다 새로 빌린 돈이 더 많았다는 뜻"). 8상 이름은 분류 라벨이라 유지. 카드마다 `anchor{zone, std_focus}`.

| 카드 | 제목(확정) | 산출 |
|---|---|---|
| d1 | **100원 팔면 몇 원이 남나** | 영업이익률 vs 표준 — 격차를 "100원당 몇 원" 프레임으로 |
| d2 | **가장 나빴던 해 — FY##** | 이 회사 최저점 연도 vs 표준의 최악 연도 — **같은 해(산업 경기) / 다른 해(개별 사정)** 판별 |
| d3 | **지금 국면 — {8상}** | 패턴이 바뀐 해와 방향 vs 표준 — 재무활동 부호의 뜻을 직관 풀이 |
| d4 | **5년간 현금이 늘었나, 줄었나** | 연도별 (OCF+ICF+FIN) 합산 누적 vs 표준 |
| d5 | **가장 다른 항목 — {계정}** | 정규화 편차 최대 흐름 계정 자동 선정 — 차트 하이라이트와 연동 |

### 6.5 무엇을 보여줄지의 선정 기준 (리더 질문 2026-08-11에 대한 답)

**델타 카드(§6) = 전 상장사 공통 고정 프레임 + 자동 선정 1장.**
d1~d4는 회사가 달라도 같은 질문을 던진다 — 초심자가 "어느 회사를 봐도 같은 순서로 읽는" 학습 일관성이 목적이고, 값·판정(같은 해였나, 국면이 바뀌었나)만 그 회사 데이터로 달라진다. 회사 고유성은 d5(편차 최대 항목 자동 선정)와 아래 notes가 담당한다.

**'눈여겨볼 곳'(notes, §7) = 이상 신호 점수 규칙이 후보를 뽑고, LLM은 서술만.**
"어디를 볼지"를 LLM 감에 맡기지 않는다 — 코드가 다음 신호를 점수화해 상위 2~4개 주석을 선정한다:
| 신호 | 규칙 (13계정+주석으로 산출) | 삼성전기 프로토에서 발화한 예 |
|---|---|---|
| 성장 괴리 | 매출채권·재고 증가율 − 매출 증가율 > 임계 | 매출 +9.9% vs 매출채권 +28.9% → n1 |
| 이익 집중 | 한 부문 영업이익 비중 > 60% | 컴포넌트 67% → n2 |
| 조달 구조 변화 | 단기/장기 차입 비중 급변·재무활동 부호 전환 | 단기 +52.5%·FIN (+) 전환 → n3 |
| 미가동 투자 | 투자 급증 + 건설중인자산 비중 > 임계 | CAPEX +76%·CIP 94% → n4 |
| 우발 요소 | 우발채무·충당부채·중단영업 주석 존재+규모 | (미발화) |
### 6.6 스토리 스레드 — 카드를 이야기로 잇는 규격 (리더 지시 2026-08-11)

카드는 독립 요약이 아니라 **위에서 아래로 하나의 이야기**로 읽힌다. 카드에 `order`(표시 순서)와 `bridge`(직전 카드에서 넘어오는 연결 문구 한 줄)를 부여하고, 렌더러가 카드 사이에 스레드 선 + bridge를 그린다. 섹션마다 도입 한 문장(`delta_intro`·`notes_intro`).

- **델타 서사 (전 상장사 공통 고정 — 빌더가 부여)**: 수익성 격차(d1) → 격차의 진원(d5) → 경기 동조(d2) → 5년 현금 결산(d4) → 최근 국면 전환(d3). bridge는 회사 무관 일반 문구("그 격차가 어디서 생기는지 …").
- **눈여겨볼 곳 서사 (생성 시 부여)**: 돈의 출처(조달) → 사용처(투자) → 현금 전환의 마찰 → 이익의 원천/구조 순으로 §6.5 신호를 배열 — 델타의 마지막 카드(국면 전환)에서 자연히 이어진다(예: 확장투자형 → "당겨온 돈은 짧은 빚" → "그 돈은 미완성 설비로"). bridge는 새 수치를 담지 않는다(게이트는 what/why만 검사).
- 카드가 빠져도(데이터 없음) 스레드가 깨지지 않게, bridge는 앞 카드가 실제 표시될 때만 렌더한다.

**산업별 차이는 T1 골든이 흡수한다**: 클러스터 표준의 주석 라우팅(골든 `meta.routing_ledger`·`note_dive`)이 그 산업에서 중요한 주석 지도를 이미 갖고 있으므로, lite의 주석 후보 시그니처를 클러스터별로 T1에서 상속한다(반도체=재고·설비·부문, 항공=리스·외화, 게임=무형자산·선수수익 등). 프로토는 공통 시그니처만 사용 — 클러스터 상속은 일괄 확장 단계 과제.

## 7. LLM '주목할 점' 카드 (2~4장) — 유일한 LLM 구간

- **선별(코드)**: `report_section`에서 제목 시그니처로 후보 6~8개 — 재고자산·매출채권·차입금·충당부채·우발채무·특수관계자·영업부문·중단영업 등.
- **압축(2단, 골든 note-extractor→prose-writer 축소판)**: 원문을 LLM에 직접 넣지 않는다. ① 규칙 추출(표 파싱·정규식, 토큰 0) → 부족분만 ② 경량 fact 추출 → ③ 카드 작성기엔 **fact-sheet만** 입력.
- **출력**: `{title, what[2문장], why[2~3문장 — 표준에서 배운 개념으로 연결], src{note_no,title}}`
- **게이트 (D7 축소판)**: 브래킷 수치가 전부 ⑴주석 원문 substring 또는 ⑵13계정 재도출 — 실패 카드만 재작성. 대조는 코드가 DB에서 수행(토큰 0).

### 7.1 토큰 경제
- 청킹 전처리 = **기존재**(`report_section` 428,420행). 신규 임베딩 불필요.
- LLM은 **기업당 1회 배치**(사업보고서 연 1회 갱신 시 증분) → 정적 JSON 서빙 → **조회 시 토큰 0**.
- 대량 확장 시: 조회 상위 기업부터 증분 생성, GPU 서버(Qwen3-32B) 로컬 생성이면 API 토큰 0.
- 임베딩·시맨틱 검색은 **비범위** — 선별이 규칙 기반. RAG(api/) 시점의 별도 과제.

## 9. 확장 로드맵

1. **반도체 프로토 검증** (현재) — 표준 삼성전자 → 삼성전기.
