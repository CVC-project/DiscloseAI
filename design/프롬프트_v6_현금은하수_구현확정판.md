# PART 1 — v5 → v6 변경 확정 목록 (본문과 충돌 시 이 파트가 우선)

## 1-1. 은하수 형태 — "구불구불" 폐지, **일직선 본류**
- v5 §3-1의 "좌우로 굽이쳐 내려오는 강(진폭 ±30~40%)"은 **폐기**. 본류는 **하나의 x좌표(`spineX:0.48`)에 고정된 일직선**으로 위→아래로 쭉 뻗는다. 매듭별 `xf` 값은 데이터에 남겨두되 `spineX`가 설정되어 있으면 무시된다.
- 본류 세그먼트는 여전히 세로 베지어(`cv()` 함수)로 그리지만 시작·끝 x가 같으므로 사실상 직선이다.
- **모든 파선(회귀·연결·골드실)은 "직교 라우팅"**: 수직·수평 직선으로 뻗고, **꺾이는 모서리만 곡선(반경 10~14px)** 처리. PART 2 §B-4의 `ortho()` 함수 사용. 프리핸드 베지어 곡선 금지.

## 1-2. 리본 굵기 — "폭=금액(√스케일)" 폐지, **2단 통일 굵기**
- v5 §3-2 ③은 **폐기**. 은하수의 모든 굵기는 두 가지뿐:
  - **본류(스파인) 전 구간: 6px** (`CONFIG.ribbon.mainW`)
  - **모든 지류(유출·유입 가지): 3.5px** (`CONFIG.ribbon.branchW`)
- 기준: "작은 줄기는 환율효과의 것으로, 큰 줄기는 환율효과→기말현금 구간의 굵기로 통일"이 사용자 확정 문구.
- 저수지(기초·기말현금 원)의 크기는 그대로 유지(rBegin 30 / rEnd 31) — 잔액 앵커의 위계는 굵기가 아닌 원 크기로.

## 1-3. 기초현금 ↔ 매출 연결 (신규)
- 상단 저수지(기초현금)와 매출 발원 성운을 **시안 본류 세그먼트로 직접 연결**한다 (`SEGS`의 첫 항목 `['k1','k2']`).
- **이격/삐짐 제로 규칙**: 세그먼트 경로를 저수지 **중심까지** 그리고, 저수지의 **불투명 배경원**(`fill:#081019`, 반지름 r−1)이 안쪽을 덮게 한다. 테두리에서 선을 끊으려 하면 1px 이격이나 삐짐이 생긴다 — 반드시 "중심까지 그리고 덮기" 방식으로.
- 하단(k14 환율효과 → k15 기말현금)도 동일한 방식.

## 1-4. 매듭 라벨 — 번호 제거 + 좌측 정렬 + 유입 매듭 오프셋
- **좌측 은하수 매듭 라벨에서 번호(01, 02, …)를 전부 제거**. 라벨은 이름(윗줄)+금액(아랫줄)만, 둘 다 `x = 매듭중심 + 15px` 좌측 정렬. (번호는 우측 스토리 카드의 "KNOT 06ᵇ · n/17" 메타 라인과 **중앙 재무제표 행**에만 남는다.)
- **유입 매듭(k6b 영업외손익, k14 환율효과)은 라벨 전체(이름·금액)를 8px 아래로** 내린다(`yOff = 8`) — 위에서 합류하는 유입 지류와 겹치지 않게. 출처 라벨 `⊕ 이자·환율·지분법` / `⊕ 환율 변동`은 `y = 매듭중심 + 36px`, 같은 x(+15) 좌측 정렬.
- k6b의 출처 문구는 **"이자·환율·지분법"** (조사 "~에서" 없이 — 본류와 겹치지 않는 길이로 확정).

## 1-5. 감가상각 회귀선 — 분기 기점·모양 확정
- 회귀 점선은 v5의 "존 B 비용 가지에서 흐리게" 대신, **매출원가(k3)·판관비(k5) 유출 가지의 끝(⊖ 글리프 아래)에서 분기**한다. 분기 x = 유출 가지 끝의 x (k3·k5 공통, `depX = max(44, k3.x + outDx)`).
- 경로: `[depX, k3가지끝y+9] → [depX, k9.y] → [k9.x−9, k9.y]` 를 `ortho(…, 14)`로 — 세로 직선으로 내려와 k9에서 수평 합류. k5 가지 끝 높이에 작은 접합점(r 2.5 시안 원).
- 스타일: 시안, 1.8px, `4 4` 점선, 평상시 opacity **0.55**, ⑨ 포커스 시 0.9.
- 칩 `현금은 안 나간 비용 / 도로 더해요 +43.6`은 k9 왼쪽 위(`k9.x−60, k9.y−34`).

## 1-6. 골드 자본 실 — 경로·색·기점 전면 확정
- **순이익→자본 실은 민트색**(손익이므로): 당기순이익 매듭(k8)에서 나와 **화면 우측 맨 끝(`niX = W−5`) 거터를 타고** 내려가 자본변동표의 `+당기순이익` 행(eq-netincome)으로 수평 진입. 경로 `[k8.x+6, k8.y+28] → [niX, k8.y+28] → [niX, yNI] → [gx+10, yNI]`, `ortho(…, 14)`, 1.8px `4 4` 점선, opacity 0.45. 칩 `이익은 주주 곳간에도 쌓여요`(민트)는 k8 오른쪽 아래(`k8.x+96, k8.y+48`). — 우측 끝 경유가 확정 이유: 중간 라벨·설명들과 절대 겹치지 않게.
- **존 E 골드 세로줄**: `gx = W−16`에 기초자본(y)~기말자본(y) 구간만 골드 2.4px 실선 + 7px 글로우. 각 사건 노드는 자본변동표 행 y에 정렬된 원(big: r8.5 / 일반: r5.5, 배당·자사주는 코랄 테두리), 금액 텍스트는 노드 왼쪽(`gx−13`, 우측정렬).
- **OCI 유입은 골드 점선**(v5의 "시안 점선"에서 변경): 경로 `[gx−56, yO−21] → [gx−56, yO] → [gx−10, yO]`, `ortho(…, 10)`, opacity 0.55. 칩 `손익 밖에서 직접 (OCI)`(골드)는 `(gx−66, yO−30)` — **칩(패널)에서 파선이 나오는 모양**이 되도록 칩 아래변에 파선 시작점이 붙는다. 파선이 칩 위로 삐져나오면 안 된다.
- **배당·자사주 연결(코랄 점선)**: ⑬ 재무활동 유출 가지 끝에서 출발 `[fx13, k13가지끝y+9] → [fx13, yDiv] → [gx−11, yDiv]`. 평상시 opacity **0.55**(다른 파선과 동일 밝기 — 확정), k13/eq-div/eq-buyback 포커스 시 0.9. 칩 `재무활동에서 나간 그 돈`(코랄)은 `(gx−96, yDiv+22)`.

## 1-7. 저수지 주변 배치 확정
- 기말 저수지 **위** 본류 중앙에 골드 칩 `+4.15조 늘었어요` (`x = k15.x`, `y = k15.y − rEnd − 26`).
- 기말 저수지 **아래** 중앙 정렬로: `올해 통장` 라벨(`y = +24`) → 등식 칩 `53.71 + 4.15 = 57.86`(`y = +44`).
- 기초 저수지 위 레일 쪽에 `작년 통장` 라벨.

## 1-8. 여정 모드 스크롤 — **제스처 기반** (여러 차례 수정 끝에 확정된 최종 알고리즘)
- **문제**: 시간 게이트·타이머 캐치업 방식은 휠 한 칸의 관성 스크롤(수백 ms 지속) 안에서 카드가 두 번 넘어가거나, 중간 카드가 300ms만 깜빡이고 지나가는 "씹힘"을 만든다.
- **확정 모델 — "스크롤 한 칸(제스처) = 카드 한 장"**:
  1. 스크롤 이벤트마다 화면 44% 지점(`centerFrac:0.44`) 기준으로 **목표 정거장**만 계산해 `_target`에 저장.
  2. **새 제스처 판정**: 직전 스크롤 이벤트로부터 **250ms 이상** 끊겼다가 다시 이벤트가 오면 새 제스처. 새 제스처일 때만 **목표 방향으로 정확히 한 칸** 이동. 한 제스처(관성 포함) 안에서는 절대 두 번 이동하지 않는다.
  3. **유휴 재동기화**: 스크롤이 450ms 잠잠해진 뒤, 현재 카드와 목표가 **3칸 초과**로 어긋났을 때만 목표로 단번에 점프. 1~3칸 차이는 그대로 두고 다음 제스처가 한 칸씩 따라간다(방금 보여준 카드를 유휴 타이머가 밀어내는 이중 전환 방지).
  4. 타이머로 중간 정거장을 순차 통과시키는 "캐치업" 절대 금지 — 중간 카드가 깜빡이며 스치는 원인.
- 정거장 순서: `overview → zoneA → k1 → zoneB → k2…k8 → zoneC → k9…k14 → zoneD → k15 → zoneE → eq-begin…eq-end → epilogue` (PART 2 §B-6).

## §A. 아키텍처

```
단일 HTML
├─ <head>: 폰트 링크(Pretendard CDN + Google Fonts IBM Plex Mono), React 18
├─ <style>: :root 토큰 + body 리셋 + @keyframes + data-jl/data-hl 규칙 + 스크롤바
└─ <body>: React 클래스 컴포넌트 Component 하나가 전체 렌더
    ├─ 배경 레이어(성운 글로우 + 저휘도 별)
    ├─ 상단 바 + 인트로(§0 재무제표 4종 + 연결 기준 + 색 범례)
    └─ [data-grid] display:grid; grid-template-columns: 2fr 3fr 5fr
        ├─ [data-left]  포지션 기준 컨테이너 — buildGalaxy()가 만든 SVG를 absolute inset:0으로
        ├─ [data-mid]   재무제표 5패널 (padding: 0 20px 55vh 10px) + buildMidOverlay() SVG(absolute, pointer-events:none, z-index:2)
        └─ [data-right] position:sticky; top:0; height:100vh; flex-col
            ├─ 모드 헤더 (JOURNEY / PINNED 바)
            ├─ 색 범례 스트립
            └─ [data-insp] flex:1; overflow-y:auto; padding:30px 36px 44px — buildCard()
    └─ buildRunningChip() — position:fixed left:14px bottom:14px (존 C 러닝 토털)
```

**핵심 설계 원칙 — 측정 기반 정렬 (하드코딩 금지)**
- 모든 매듭·노드·연결선의 y좌표는 **중앙 재무제표 행의 실제 y를 측정**해서 파생한다. 행마다 `data-row="<id>"`, 존 헤더마다 `data-zone="zoneA~E"` 속성.
- `measureNow()`: `[data-left]` 기준 rect에서 각 `[data-row]`의 중심 y(`pos` 맵)와 `[data-zone]`의 y(`zoneY` 맵), 그리고 `[data-mid]` 기준의 `{y, x1, x2}`(`midPos` 맵 — 오버레이용)를 구해 state에 저장. **시그니처 문자열**(W|H|주요행 y 5개)이 같으면 setState 생략(무한 재렌더 방지).
- 재측정 트리거: mount 직후 rAF → `ResizeObserver`([data-mid], [data-left]) → `window.resize` → `document.fonts.ready` → mount 600ms 후 1회. 모두 rAF로 큐잉(`queueMeasure`).

ortho = (pts, r = 12) => {           // pts: [[x,y],...] 꺾은선 → 모서리만 Q 곡선
  let d = `M ${pts[0][0]} ${pts[0][1]}`;
  for (let i = 1; i < pts.length - 1; i++) {
    const [x0,y0] = pts[i-1], [x1,y1] = pts[i], [x2,y2] = pts[i+1];
    const l1 = Math.hypot(x1-x0, y1-y0), l2 = Math.hypot(x2-x1, y2-y1);

  }
  return d + ` L ${pts.at(-1)[0]} ${pts.at(-1)[1]}`;
};

### 3-2. 흐름을 읽히게 하는 6가지 장치 (반드시 전부)

**① 두 개의 큰 저수지 = 시작/도착 앵커**
- 맨 위 **기초현금 53.71조**, 맨 아래 **기말현금 57.86조**를 다른 매듭보다 **확연히 큰 발광 원(disc)** 으로. **저수지=잔액(정적인 큰 원), 리본=흐름(흐르는 띠)** 로 시각적으로 명확히 구분.
- 기말 저수지에 **"+4.15조" 델타 칩**을 붙여 "통장이 이만큼 불었다"로 이야기가 그림으로 끝나게. **[v6: 배치는 PART 1 §1-7]**

**② 좌측 끝 ⊕/⊖ 원장 레일 (레이아웃 JPEG의 좌측 주석 그대로)**
- 은하수 왼쪽 끝에 얇은 세로 거터. 위 앵커 `작년 통장 53.7조`와 아래 앵커 `올해 통장 57.9조`를 가는 세로선으로 잇고, 각 매듭 높이에 **⊕(들어옴, 시안/민트)·⊖(나감, 코랄)** 기호를 정렬한다.
- → 글자를 읽기 전에도 "이건 더하는 것 / 이건 빼는 것"이 한눈에.
- **레일 = 진행 게이지 겸용**: 스크롤 중인 현재 매듭의 기호가 가장 밝게 빛나 "53.7 → 57.9 여정의 지금 위치"를 겸한다(별도 게이지를 또 만들지 않는다).
- **⚠️ 레일은 '더하기표'가 아니다**: 손익 항목(매출·원가 등)은 그 자체로 현금이 아니므로, 레일 기호는 **방향 표시(정성)로만** 쓰고 숫자를 세로로 합산시키지 말 것(더해도 57.9가 나오지 않아 초심자가 혼란). 산수는 맨 아래 앵커의 **등식 칩 하나**로 끝낸다 — `53.71 + 4.15 = 57.86` ("작년 통장 + 올해 늘어난 만큼 = 올해 통장").

**③ 폭 = 금액** — ~~√스케일 압축 밴드~~ **[v6 폐기: 2단 통일 굵기 — PART 1 §1-2]**

**④ 지류(가지) + 도착지·출처 칩 — 좁은 폭이므로 짧게, 항상 아래로**
- **유출(코랄)**: 본류에서 **왼쪽 아래 방향**으로 짧게 갈라져 나가, 끝을 **⊖ 글리프 + 도착지 칩**으로 맺는다: 매출원가 →`협력사·부품·재료로`, 판관비 →`직원·광고·R&D로`, 법인세 →`나라(세금)로`, 투자 →`새 공장·장비로`, 재무 →`주주에게`. "돈이 사라진 게 아니라 누군가에게 갔다." **왼쪽 = 레일 쪽 = 회사 밖.**
- **유입(시안/민트)**: **오른쪽 위에서 아래로 흘러 들어와** 본류에 합류하고, 합류점에 **⊕ 글리프**: 영업외·금융손익 +5.9, 환율 +0.8. **오른쪽 = 재무제표 쪽 = 이야기에서 온 돈.** (⑨ 비현금 조정 +52.4만 예외적으로 **왼쪽에서 되돌아 합류** — ⑥의 회귀 문법. 오른쪽 유입으로 중복해 그리지 말 것.)
- **★ 발원에도 출처 칩**: ② 매출 발원 성운 위에 `고객이 낸 돈` 칩. 나가는 돈마다 도착지가 있듯, **들어오는 돈의 출처**도 보여준다.
- 가지는 절대 위로 꺾이지 않는다(대원칙). 인접한 가지·칩이 겹치면 세로 간격을 벌려 해소한다. **[v6: 유입 매듭 라벨 오프셋 — PART 1 §1-4]**

**⑤ 높이 정렬 = 유기적 연결의 공간화 (구현 규칙 포함)**
- **각 매듭의 y좌표 = 중앙 재무제표에서 그 항목 행의 y좌표.** 매듭↔행 연결선이 **수평선**이 되는 것이 정렬의 합격 기준이다.
- **★ 구현 규칙 (하드코딩 금지)**: 매듭 위치를 임의 좌표로 박지 말 것. 중앙 재무제표를 먼저 렌더링한 뒤 **각 행의 실제 y를 측정해 매듭과 곡선을 그 y에 맞춰 배치**한다(재무제표 행 위치가 단일 진실 공급원). **[v6 구현: PART 2 §A 측정 파이프라인]**
- ⑧ 당기순이익 매듭은 **손익계산서의 당기순이익 행**에 정렬한다(현금흐름표 첫 행의 당기순이익과는 §4-3의 초록 화살표가 잇는다).

**⑥ 감가상각 "나갔다 되돌아옴" = 한 숫자, 세 얼굴**

> **★ 용어 규칙**: "장부이익" 금지(혼란). 대신 **"손익상 이익"** 또는 **"손익 계산상 이익"**.

## 4. 중앙 — 재무제표 (원문 수준, 각 줄 클릭 가능)

레이아웃 JPEG 순서 그대로 위→아래로 스택. **각 줄이 클릭 가능**하며, 클릭 시 §6 인터랙션 발동. 디자인은 참고자료 PNG의 **코너 브래킷 HUD 카드** + 색 헤더바(IS=민트/CF=시안/자본=골드/BS=스틸) + 모노스페이스 숫자. 각 패널 헤더에 §0-1 한 줄 소개를 서브카피로.
- 5개 패널은 §3-1의 존 A~E에 하나씩 놓인다(A 전기BS · B 손익계산서 · C 현금흐름표 · D 당기BS · E 자본변동표).
- **소계 행(매출총이익·영업이익·세전이익·당기순이익·각 활동 합계 등)은 일반 행보다 굵고 밝게** — 표의 계단 구조가 훑어만 봐도 스캔되게.
- **★ 소계는 항상 세부 아래(계산 순서)**: 원문처럼 `Ⅰ. 영업활동 85.3` 합계를 섹션 맨 위에 두면 ⑪ 영업CF 매듭이 ⑨·⑩보다 위로 가야 해 **"시간은 아래로" 대원칙(§3)과 충돌**한다. 모든 소계·합계 행은 그 세부 행들 **아래**에 놓는다.
- **★ 행 리듬 = 은하수의 숨 쉴 공간**: 존 B·C의 행높이는 행당 최소 ~64px 기준으로 넉넉히, 세부 행은 **기본 접힘(▸)**. 호버·발광 대상 행이 접혀 있으면 자동으로 펼친다.

### 4-1. 전기말 재무상태표 — 현금만 간단히
- `현금및현금성자산 53.7조` **한 줄만**. 좌측 기초현금 저수지와 같은 높이.

### 4-2. 손익계산서 (당기) — 원문 수준 전체
매출액 +333.6 → −매출원가 202.2 → **=매출총이익 131.4** → −판관비 87.8 → **=영업이익 43.6** → **+영업외·금융손익 5.9**(기타수익 2.3 −기타비용 1.6 +지분법이익 0.7 +금융수익 16.2 −금융비용 11.7) → **=법인세차감전순이익 49.5** → −법인세 4.3 → **=당기순이익 45.2**(지배 44.3 / 비지배 0.9) → … → **기타포괄손익 6.1** → **총포괄손익**.
> ※ 영업외·금융손익(+5.9)과 세전이익(49.5)을 빼먹지 말 것 — 영업이익 43.6에서 곧장 45.2로 가면 6조가 어긋납니다.

### 4-3. 현금흐름표 — 세 활동 동등 위계(들여쓰기 금지)
- **영업활동 = +85.3** ← 당기순이익 +45.2 / 비현금 조정 +52.4(감가상각 43.6 최대) / 운전자본 변동 −9.6 / 이자·법인세 실납부 −2.7.
- **투자활동 = −68.5** ← 유형자산 취득 −47.5 / 무형·관계기업·기타 −21.0.
- **재무활동 = −13.5** ← 차입금 순증가 +4.6 / 배당 지급 −9.9 / 자기주식 취득 −8.2.
- **외화환산효과 = +0.8** → 기초현금 53.7 + 순증 4.15 = **기말현금 57.9**.
- **★ 초록 화살표(JPEG)**: 손익계산서의 **당기순이익 45.2** 줄 → 현금흐름표 영업활동의 **당기순이익 45.2** 줄로 이어지는 연결선.

### 4-4. 당기말 재무상태표 — 주요 라인 + 드롭다운 전체 라인 (★ 자산 = 부채 + 자본)
- **주요 라인(기본 표시)**: 자산총계 566.9 · 부채총계 130.6 · 자본총계 436.3 · 그 아래 현금 57.9조 강조. 좌측 기말현금 저수지와 같은 높이.

  - **자산** ▸ 유동자산(계 247.7)·비유동자산(계 319.3) → 각 세부(현금·매출채권·재고·유형자산·무형자산·관계기업투자 …)

  - **자본** ▸ 지배주주지분(계 424.3: 이익잉여금 402.1·기타자본 16.9·주식발행초과금 4.4·자본금 0.9)·비지배지분(12.0)

### 4-6. ★ 합계 정합성 철칙
**모든 대분류 금액 = 하위 항목들의 합**과 정확히 일치. 현금 체인은 **순증 델타 칩 "+4.15조"** 하나로 제시(53.71 → 57.86). 저수지·순증 칩은 소수 둘째 자리. 미세 차액은 "그 외 ±0.x조" 한 줄 또는 툴팁 원본(백만원) 병기로 흡수.

## 5. 우측 — 고정 설명 인스펙터 (50%, 스크롤 무관 sticky)

### 5-1. 두 가지 모드 — 여정(스크롤) / 핀(클릭)
**"초심자는 클릭하지 않는다"는 전제**로, 스크롤만으로도 이야기가 완주되게 한다:

- **여정 모드 (기본)** — 스크롤을 따라가는 내레이션. 카드 교체는 크로스페이드(180ms), 정거장 사이 구간에서는 직전 카드를 유지한다(빈 화면 금지). **[v6 스크롤 모델: PART 1 §1-8 — 제스처당 한 장]**
  - **정거장 목록**: 존 제목 카드 5개 + 매듭 17개 + 존 E 골드 사건 7개 + **에필로그 카드 1개**.
  - **스토리 카드 구성**: 존 뱃지(A~E) + 매듭 번호·이름·**금액(크게)** + 이야기 카피 + `자세히 보기 ▸` 버튼(핀 모드로 진입).
- **핀 모드** — 매듭이나 재무제표 줄을 **클릭**하면 그 항목의 4단 딥다이브(§5-2)로 고정된다. 상단에 `✕ 흐름으로 돌아가기` — 클릭(또는 Esc)하면 여정 모드로 복귀. 핀 상태에서는 스크롤해도 내용이 바뀌지 않는다.

### 5-2. 핀 모드의 4단 구조 (모든 클릭 항목 공통 골격)
1. **① 무엇인가요 — 정의·의미**: 2~4문장.
2. **② 어디와 이어지나요 — 재무제표 연결 지도**: (표 이름 + 행 + 방향·금액) 한 줄씩. **각 줄에 호버하면 중앙의 해당 행이 발광.** 리스트 아래에 연결의 의미를 한 문장으로. 다른 표와 이어지지 않는 항목이면 억지로 만들지 않는다.
3. **③ 왜 그런가요 — 규정 또는 시각화**: *"왜 이런 규칙이 있냐면 —"* 프레임, 그래픽에는 **"이 그림이 말하는 것" 한 줄 캡션**.
4. **④ 5년간 어땠나요 — 증감분석**: §8 시계열 그래프 + §8-3 해석 + **"그래서?" 한 문장**. **⚠️ §8에 없는 항목은 5개년 수치를 지어내지 말고** skip 문구로 대체.

**★ 타이포그래피 규칙**: 한 문단 = 2~3문장 · 첫 문장이 결론 · 숫자는 강조 칩 · 문단마다 볼드 하나만.

### 5-3. 기본 상태 (스크롤 전)
**개요 카드**: "삼성전자의 1년을 한 문장으로 — 333.6조를 벌어 45.2조를 남겼고, 통장 현금은 4.15조 늘었어요." + 사용법 + JOURNEY MAP(존 5줄).

### 5-4. ★ 자본변동표 설명 특칙

## 6. 인터랙션 (한 항목 = 세 곳 동시 반응 + 양방향)

- **(A) 클릭 → 동시 발광 + 핀**: ① 좌 은하수 매듭 발광 ② 그 항목이 나오는 **모든 재무제표 줄** 동시 발광 ③ 우 인스펙터 핀 모드 4단 로드. `✕`/Esc로 복귀.

## 4-2. ★ Dive 객체 스키마 (주석·항목 설명의 저작 계약)
`getDives()`의 `D.<key>`가 갖는 형태. `diveCard`가 이 필드들만 소비한다(다른 표에 안 이어지면 `links`를 억지로 만들지 말 것):
```js
D.<key> = {
  z, zc,          // 존 뱃지 글자 + 색이름 ('mint'|'cyan'|'gold'|'coral'|'steel')
  en, name,       // 영문 라벨(대문자) + 한글 제목(25px)
  amt, raw,       // 큰 금액 문자열(42px) + 원본 백만원 문자열(없으면 필드 생략)
  color,          // 메인 색 (this.C.xxx 값)
  row,            // (선택) 연결 data-row id — '은하수에서 이 항목 보기' 버튼·발광 대상
  what:  [ '문단1', '문단2' ],                         // ① 무엇인가요 — [대괄호]=강조칩 자동
  links: [ { t:'IS'|'CF'|'BS'|'PBS'|'EQ'|'N', row:'<data-row>', txt:'설명', a:'금액' } … ], // ② 연결 지도(줄 호버→중앙 행 발광)
  lnote, // (선택) ② 아래 한 줄 정리 — ★특칙: oci·eq-* 카드는 CE↔OCI↔재무CF 관계를 여기 필수 명시
  why:  { sub:'소제목', body:['문단'], viz:()=>this.vWater({…}), cap:'이 그림이 말하는 것' }, // ③ 왜(viz·cap 선택)
  five: { key:'op', color, valley:2, zero:false, cap:'…', so:'그래서 한 문장' } // ④ 5개년
        // 대안: { twin:{ a, b } }  (쌍막대) / { skip:'시계열 없음 사유' } (그래프 생략)
}
```
- `t` = §B-11 `TBL` 키(6종): `IS`=손익계산서(민트) · `CF`=현금흐름표(시안) · `BS`=재무상태표(스틸) · `PBS`=전기말 BS(스틸) · `EQ`=자본변동표(골드) · `N`=주석(dim).
- `five.key`/`twin.a,b` = §B-12 `S` 시계열 키. **S에 없는 시계열을 지어내지 말 것 → `{skip}`** (§5-2 ④단 규칙).

## 4-6. ★ 해방판(standalone) 로컬 런타임 — 정본 실행 형태
받은 산출물은 Claude `x-dc` 번들(소스가 이스케이프 문자열로 내장 → 손편집 불가)이다. **최종 로컬 파일은 x-dc 런타임을 버리고 표준 React로 재호스팅**한다. 로직·템플릿·CSS는 그대로 재사용하므로 픽셀 동일이 보장된다:
- **head**: React/ReactDOM 18.3.1(unpkg 핀 버전) + Pretendard(jsDelivr `pretendard@1.3.9`)·IBM Plex Mono(Google Fonts) + §B-13 `<style>`(**omgrow 포함**).
- **`DCLogic` shim** (x-dc 대체): `class DCLogic { constructor(p){this.props=p||{};this.state={}} setState(u,cb){this.state={...this.state,...(typeof u==='function'?u(this.state):u)}; this.__host&&this.__host(); cb&&cb();} }` — setState가 호스트 재렌더를 부른다.
- **셸 호스팅(재호스트)**: 템플릿 정적 마크업은 그대로 두고, `{{ onRow }}`류는 **이벤트 위임**(click→`closest('[data-row]')`.dataset.row→`logic.onRow` / `[data-g]`→`logic.onToggle`)으로 대체. 엘리먼트 슬롯 4개는 React 서브루트/포털로 각 컨테이너에 주입. `exp/car`는 렌더 후 명령형으로 detail-row `display`·캐럿 글리프 갱신. 헤더는 `isPinned`로 클래스 토글.
- **공짜로 동작하는 것**: 로직의 `measureNow`·`applyJourneyHL`·`scrollToRow`·`hoverRow`는 이미 `document.querySelector('[data-row]'/'[data-zone]')` 기준이라 프레임워크와 무관하게 그대로 돈다. `componentDidMount`가 스크롤·ResizeObserver·`document.fonts.ready`·Esc(keydown)를 스스로 배선한다.
- **검수**: 브라우저에서 원본 번들과 스크린샷 대조 + §10 성공기준 통과 + "dive 객체 1개 추가 → 즉시 반영" 확인.
