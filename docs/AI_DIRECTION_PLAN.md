# DiscloseAI — AI 활용 방향 실행 계획 (Plan)

본 문서는 도전제안서에서 확정한 DiscloseAI의 AI 활용 방향을 **기술 실행 관점에서 구체화한 계획서**다.
제안서 §2(아이디어 상세 및 차별점)·§3(구현계획 및 추진일정)의 기술 내용을 기준으로 삼고, 각 응용 기능의 **상세 설계·2026 기술 스택·현재 모듈 구조와의 결합**까지 확장한다.

---

## 1. 제품 구조 (확정)

DiscloseAI는 KOSPI·KOSDAQ 2,600개 상장사를 별·성운으로 시각화한 **Corporate Universe** 위에서, 4개 기존 모듈의 협업 분석(현재 구현)과 그 위에 얹히는 **응용 3기능 + 통합 1기능**으로 구성된다.

| 구분 | 기능 | 담당 모듈 |
|---|---|---|
| **기반 (현재 구현)** | Corporate Universe + 4모듈 협업 분석 + 공시 타임머신 | financial · disclosure · relation · price |
| **응용 ①** | Corporate 방탈출 — 위험 시그널 추리 게임 | financial + disclosure |
| **응용 ②** | 도미노 이펙트 — 인과 그래프 동적 생성 | relation |
| **응용 ③** | 새도우 포트폴리오 — 다중 투자 페르소나 | price |
| **통합 ④** | 개인 학습 통합 레이어 — 누적·복습·진단 플랫폼 | 전체 통합 |

3개 응용 기능 위에 4번째 통합 레이어가 깔려야 비로소 **단발 경험 → 맞춤형 학습 플랫폼**이 된다.

### 메타 정체성

> **"4명의 CPA가 만든, 한국 공시의 행간을 읽고, 사용자와 함께 자라는 AI 학습 환경."**

| 레이어 | 사용자 관점 | 훈련 영역 |
|---|---|---|
| **도미노** | "공시 한 줄이 어디까지 퍼지는가" | 시스템 사고 |
| **방탈출** | "이 회사 어디에 위험이 숨었는가" | 위험 시그널 추리 |
| **새도우** | "그 시점에 나는 어떻게 결정했을까" | 자기 객관화 |
| **개인 학습 우주** | "내가 무엇을 배웠고 무엇이 부족한가" | 메타 학습 |

3개 응용 기능은 **"AI가 답을 주지 않는다, 사용자가 스스로 답에 도달하게 한다"** 라는 일관된 메시지를 공유하고, 통합 레이어는 그 경험을 **"흩어진 단발 → 누적된 자산"** 으로 변환한다.

## 2. 아이디어 상세 및 차별점

### 2.1 주요 기능 및 시나리오

기업 우주(WebGL)에서 기업 하나를 클릭하면 4개 모듈이 협업해 통합 분석을 제공한다. 응용 3기능은 이 분석을 기반으로 사용자의 사고력을 단계적으로 확장한다.

**현재 구현 — 4모듈 협업 분석**

| 모듈 | 역할 |
|---|---|
| **financial** | 복잡한 재무제표를 이익품질지표(EQS)로 변환하고 최근 변동 추이를 분석해 누구나 알기 쉽게 해설 |
| **disclosure** | 과거뿐 아니라 실시간으로 공시를 수집해 기업에 미치는 Risk·Hidden Agenda를 즉시 분석 |
| **relation** | 공정위 계열사·K-IFRS 지분 관계를 기준으로 기업 관계망을 탐색 |
| **price** | 과거 공시가 주가에 미친 영향을 퀴즈(공시 타임머신)로 체험하게 하고, AI 챗봇과 함께 학습 능률 향상 |

**응용 3기능 + 통합 1기능 — 사고력 확장 (상세 설계는 §4)**

| 기능 | 한 줄 시나리오 |
|---|---|
| **Corporate 방탈출** | 대우조선해양 등 실제 사례를 바탕으로 재무제표·공시에 숨은 Red Flag 패턴을 추리하는 학습 게임. 사용자가 스스로 위험 신호를 발견하도록 유도. 분식뿐 아니라 합법이지만 고위험인 공시, 위기 전조 시그널까지 3가지 범주를 다룸 |
| **도미노 이펙트** | 특정 기업의 공시·사건이 다른 기업에 미치는 영향을 relation 모듈을 응용해 인과적으로 추적. 공시 한 줄의 영향이 어디까지 퍼지는지 단계적으로 확인 |
| **새도우 포트폴리오** | 과거 시나리오에서 다양한 투자자 페르소나가 같은 공시·사건을 어떻게 판단했는지 비교. 사용자 자신의 의사결정 패턴과 대조해 사고를 확장 |
| **개인 학습 통합 레이어** | 도미노·방탈출·새도우에서 쌓인 학습 자취를 사용자별로 누적·관리. BKT 숙련도 추적으로 개념별 이해도를 실시간 진단하고, 망각 곡선 기반 복습 큐가 약점 개념을 잊기 전에 다시 제시. 매주 AI 학습 리포트로 강점·약점을 시각화해 단발 경험을 학습 자산으로 성장시킴 |

### 2.2 창의성과 차별점

한국에 없는 기업 시각화와 AI 기반 사고력 확장으로 기존 금융 플랫폼과 차별화한다.

**창의성**
- **기업 우주** (KOSPI·KOSDAQ 2,600개): 상장사 전체를 별·성운으로 시각화한 한국 최초의 기업 탐색 서비스. 복잡한 목록·텍스트 대신 직관적 우주 지도로 누구나 쉽게 접근 → *"검색이 아닌 탐험으로 기업을 만나다."*
- **공시 타임머신** (과거 시점 체험): 과거 특정 시점으로 이동해 당시 공시·뉴스를 그대로 체험. 미래를 모르는 상태에서 스스로 시그널을 발견하도록 자기 학습을 유도 → *"당신이라면 어디서 알아챘을까?"*

**차별성**
- **응용 사고력 확장 메커니즘** (단계적 확장): 재무제표·공시 이해를 바탕으로 사고력을 단계별로 확장 → **도미노(시스템 사고) → 방탈출(위험 추리) → 새도우(자기 객관화).**
- **개인별 맞춤형 AI 금융 플랫폼** (진정한 개인화): 같은 대시보드가 사용자마다 다르게 보이는 맞춤형 학습 환경 → 숙련도 추적 / 약점 진단 / 주간 리포트 / 망각 곡선 복습.

### 2.3 AI 활용 계획 — 3대 원칙

**환각 방지·역할 통제·학습 메모리**의 3가지 핵심 원칙으로 구조화하여, 응용 3기능과 통합 학습 레이어 전체에 일관되게 적용한다. (각 기술의 심화 설계는 §3)

#### ① 환각 방지 — Citation-Enforced GraphRAG

| 단계 | 내용 |
|---|---|
| **구축** | DART 공시 데이터를 Knowledge Graph로 구성. 각 노드(공시·기업·사건)에 공시 번호·날짜·페이지를 메타데이터로 부착 |
| **적용** | 응답 생성 파이프라인에서 **출처 노드 없이는 응답이 반환되지 않도록 코드 레벨에서 차단** (프롬프트 지시만으로는 불충분) |
| **검증** | 출처 포함 응답 비율 메트릭 추적. 도미노 이펙트 인과 노드마다 공시 번호 자동 검증(단위 테스트) |
| **최적화** | 공시 텍스트 청킹 크기 조정, 그래프 엣지 가중치 튜닝으로 검색 정확도 향상 |
| **효과** | **가짜 정보 차단** — 응용 챗봇은 답변 시 출처 페이지를 반드시 명시, 출처 없으면 답변 거부. 도미노 인과 노드마다 출처 명시 |

#### ② 역할 통제 — LangGraph + LangChain Agent

| 단계 | 내용 |
|---|---|
| **설계** | 방탈출 GM·새도우 페르소나의 허용/금지 상태를 LangGraph 노드와 조건 엣지로 명시한 State Machine 정의 |
| **적용** | 정답 유도·미래 사실 언급 등 이탈 시도를 conditional edge에서 감지해 즉시 리다이렉트 |
| **검증** | 레드팀 테스트 — 다양한 역할 이탈 유도 시도에 대한 Agent 차단율(이탈 탐지율) 측정 |
| **최적화** | 실사용자 이탈 시도 패턴을 수집해 엣지 조건에 반영, 엣지케이스 누적 관리 |
| **효과** | **역할 이탈 방지** — 방탈출 GM은 정답 누설 불가, 새도우 페르소나는 미래 사실 누설 불가·정해진 관점과 시점에서만 답변하도록 강제 |

#### ③ 학습 메모리 — Zep Graphiti (시계열 메모리)

| 단계 | 내용 |
|---|---|
| **구축** | 문제 풀이·공시 읽기·게임 진행 등 모든 학습 행동을 시계열 이벤트 노드로 Graphiti에 저장 |
| **적용** | 초기 오답률 기반 약점 진단 — 오답률 60% 초과 → 약점 태그 → 다음 세션에 관련 콘텐츠 우선 노출 |
| **검증** | A/B 테스트 — 메모리 기반 맞춤 그룹 vs 일반 그룹의 학습 지속률·정답률 비교 |
| **최적화** | 망각 곡선에 맞춰 memory decay 파라미터 튜닝, 세션 간 컨텍스트 연결 정확도 개선 |
| **효과** | **맞춤형 학습 환경** — 사용자별 학습 자취를 시간 흐름에 따라 영속 저장. 숙련도 추적·약점 진단·복습·주간 리포트의 메모리 기반 |

## 3. 공통 기반 인프라

§2.3의 3대 원칙을 구현하는 공통 인프라. 3개 응용 기능 모두가 의존하는 **LangGraph(워크플로우 제어)** 와 **Citation-Enforced RAG(출처 강제)** 가 기반이며, **Zep Graphiti**·**그래프 저장소**는 기능별로 필요 강도가 다르다.

### 3.1 컴퓨팅 백엔드 — 로컬 GPU + AWS Bedrock (하이브리드 라우팅)

위 라이브러리(LangGraph·LangChain·RAG·Graphiti)는 **로직·흐름 제어만** 담당하고 모델 자체는 품지 않는다. 실제 연산은 두 종류의 **모델 백엔드**에서 일어나며, 작업 성격에 따라 둘을 나눠 쓴다.

> **GPU란?** "똑같은 수치 계산을 수만 번 동시에" 처리하는 칩. **모델 학습 전용이 아니라**, 완성된 모델을 돌리는 **추론(inference)** 과 **임베딩·그래프 연산**에도 똑같이 쓰인다 — 대부분의 AI 서비스가 GPU를 쓰는 지점은 학습이 아니라 이 추론·연산이다.
>
> **AWS Bedrock이란?** 여러 LLM(Claude·Llama 등)을 **단일 키로 호출하는 허브**. §3.3에서 확정한 "LLM 중립" 설계를 그대로 실현해, 모델을 코드 변경 없이 갈아끼울 수 있다.

**백엔드 라우팅 원칙**

| 호출 성격 | 백엔드 | 이유 |
|---|---|---|
| **고빈도·저난도** (judge 채점, 힌트 초안, 요약, KG 추출, Graphiti 엔티티 추출) | **로컬 GPU 셀프호스팅 모델** (Solar-Ko/Qwen/Llama 등) | 호출이 잦아 외부 API로 처리하면 비용이 누적 → 자체 GPU에서 흡수 |
| **임베딩·그래프 연산** (RAG/Graphiti 벡터화, GNN, 리랭킹) | **로컬 GPU** | LLM이 아닌 병렬 연산. 2,600개 인덱싱을 로컬에서 일괄 처리 |
| **저빈도·고난도** (출처 강제 최종 답변, 페르소나 추론, 인과 검증) | **Bedrock(Claude)** | 회계 추론 품질이 결정적인 소량 호출만 고품질 모델로 |

> **핵심 시사점**: 임베딩과 고빈도 LLM 호출(특히 Graphiti는 사용자가 활동할 때마다 LLM을 부른다)을 모두 외부 API로 보내면 비용이 빠르게 누적된다. 이를 **로컬 GPU가 흡수**해야 스택 전체가 지속 가능하며, 어려운 추론만 Bedrock으로 보낸다. **LangGraph가 이 라우팅을 워크플로 노드 단위로 지정**한다(노드 A→로컬, 노드 B→Bedrock).

**GPU 활용 3단계** (뒤로 갈수록 활용도 ↑)
1. **임베딩·그래프 연산 로컬화** — RAG/GraphRAG 인덱싱·GNN. 난이도 낮고 즉시 효과.
2. **오픈 LLM 셀프호스팅** — 완성된 한국어 모델을 GPU에 띄워 고빈도 호출 처리(학습 없음, vLLM/Ollama).
3. **도메인 파인튜닝(선택)** — QLoRA로 오픈 모델에 회계·공시 데이터 + Red Flag 패턴을 경량 학습시켜 "회계 언어를 이해하는 자체 모델"로 만든다 → 단순 API 래퍼와 구별되는 차별점.

GPU 집중 작업(2,600개 인덱싱·셀프호스팅·파인튜닝)은 본선·결선 구간에 배치한다(§5.3). 예선의 50개 프로토타입은 소량 호출로 충분해 GPU 의존이 없다.

### 3.2 Citation-Enforced GraphRAG — 출처 강제 검색 시스템

**한 줄**: AI가 답할 때 반드시 출처 페이지를 인용하게 강제하고, 출처가 없으면 답변을 거부.

> **왜 GraphRAG인가?** 일반 RAG는 텍스트 조각을 그대로 검색하지만, GraphRAG는 텍스트를 지식 그래프(노드+엣지)로 변환해 다단계 추론 정확도가 약 3.4배 높다.
>
> **LazyGraphRAG**: 같은 결과를 인덱싱 비용 10–90% 절감으로 얻는다 — top50 × 사업보고서 토큰 수백만 처리에 필수.
>
> **Citation-Enforced의 의미**: 답변마다 페이지 단위 anchor를 붙이고, 신뢰도 임계 미달 시 답변을 거부하는 것을 기본값으로 한다.

**위치**: `api/middleware/rag/` (NEW, 리더 소유 — `modules/integration/CLAUDE.md` 모듈 경계 예외 적용)

**백엔드 활용**: 사업보고서 임베딩(수백만 청크)은 **로컬 GPU**에서 일괄 생성하고, GraphRAG의 KG 노드·엣지 추출은 고빈도 LLM 호출이라 **로컬 셀프호스팅 모델**로 처리한다. 출처 강제 최종 답변 생성만 품질이 중요하므로 **Bedrock(Claude)** 으로 보낸다. (라우팅 원칙 §3.1)

### 3.3 멀티 에이전트 오케스트레이션 — LangGraph + LangChain Agents

**한 줄**: LLM(Claude/Gemini/GPT 등) 위에 "역할·도구·기억"을 얹어주는 라이브러리 레이어. AI 본체가 아니라 SDK이며, SDK 선택은 LLM 선택과 분리된다.

> **개념 분리**
> - **LLM (AI 본체)**: Claude / GPT / Gemini / Llama 등 답변 생성 엔진.
> - **에이전트 SDK (라이브러리)**: LLM에게 "당신은 GM이야", "이 DB 도구를 써", "이전 대화를 기억해" 같은 지시·도구를 자동화하는 코드 레이어. SDK를 바꿔도 같은 LLM을 쓸 수 있다.

**확정: LangGraph + LangChain Agents (LLM 중립)**
- Claude/Gemini/GPT 어느 것을 주력으로 써도 코드 변경이 최소화된다.
- 비용·정책 변동 시 LLM 교체가 자유롭다 (락인 없음).
- 동등한 다중 에이전트·서브에이전트 구현이 가능하며, 한국에서 Gemini/Claude/GPT/Solar 등 다양한 옵션을 활용할 수 있다.
- **백엔드 라우팅**: LangChain의 모델 추상화로 워크플로 노드마다 백엔드를 지정한다 — `ChatBedrock`(→ Claude) 또는 로컬 추론 엔드포인트(vLLM/Ollama로 띄운 셀프호스팅 모델). **같은 그래프 안에서 고빈도 노드는 로컬 GPU, 고난도 노드는 Bedrock**으로 섞을 수 있다(§3.1).

### 3.4 시계열 에이전트 메모리 — Zep Graphiti

**한 줄**: 시간에 따라 변하는 사실을 유효기간과 함께 추적하는 AI 메모리.

> 일반 메모리는 "A는 B다"만 저장하지만, **Graphiti는 "A는 2024-03~09에 B, 2024-10부터 C"** 라는 유효기간(validity window)을 함께 저장한다. 이 유효기간이 시점 격리·변경 이력 추적·약점 진단의 기반이 된다.

**기능별 활용**
- **도미노**: "이 인과는 2024 4분기 기준" 같은 시점 명시.
- **방탈출**: "이 회사 감사인은 2014에 변경됐다" 같은 변경 이력 추적.
- **새도우**: **time-leakage 방지의 핵심** — 페르소나에게 시나리오 시점 이후 사실을 차단.
- **학습 레이어**: 학습 행동을 시계열 이벤트로 저장하고 망각 곡선에 맞춰 decay.

**백엔드 활용**: Graphiti는 학습 이벤트마다 임베딩 + 엔티티·관계 추출 LLM을 호출하는 **고빈도 컴포넌트**다. 이 호출을 **로컬 GPU 셀프호스팅 모델**로 처리해야 비용이 누적되지 않고 상시 가동이 가능하다(§3.1).

### 3.5 그래프 저장소 — networkx → Neo4j

**한 줄**: 기업 관계망과 인과 사슬을 저장·조회.

> **networkx**: 파이썬 라이브러리. 메모리에 그래프를 올려 분석. 빠르지만 영속성 없음.
> **Neo4j**: 그래프 전용 DB. 디스크 영구 저장 + Cypher 쿼리(`MATCH (a)-[:공급]->(b)`).

**전략**: MVP는 networkx (현재 `graph_top50.json`을 그대로 활용, 의존성 추가 없음, 50기업 규모로 충분) → 본격 운영 시 Neo4j Aura 무료 티어로 승격.

## 4. 기능별 상세 설계

### 4.1 Corporate 방탈출 — 위험 시그널 추리 게임 (financial + disclosure)

#### 핵심 컨셉

위험한 자동 분식 탐지 대신 **게임화된 학습**.
- AI는 **게임 마스터(GM)** 역할 — "답을 주지 않고, 사용자가 찾도록 유도".
- 과거 실제 케이스 → 시나리오 데이터셋 (분식뿐 아니라 합법적 위험 시그널 포함).
- 점진적 힌트 시스템 — 사용자 수준에 맞춰 자동 조절.
- 발견할 Red Flag → CPA 4명이 직접 작성하는 **도메인 IP**.

**케이스 범주 3가지**

| 범주 | 예시 | 학습 포인트 |
|---|---|---|
| **A. 분식회계** | 대우조선해양 작업진행률 조작, 모뉴엘 가공무역 | 회계처리 자체의 위반 |
| **B. 합법이지만 주가 충격을 준 공시** | 유상증자 직후 -20%, 무상증자 후 매도 폭주, 대규모 CB·BW 발행, 갑작스런 자사주 처분 | 합법이지만 투자자 손실로 직결되는 시그널 |
| **C. 주가 영향은 없지만 눈여겨볼 시그널** | 감사인 변경, 사외이사 무더기 사임, 특수관계자 거래 급증, 종속회사 잦은 흡수합병, CEO 메시지 톤 변화 | 위험의 "전조" — 폭발 전 작은 균열 |

→ 분식만 다루면 "사기꾼 잡기 게임"이 되어 부정적. 범주 B·C까지 포함하면 **"투자자가 평소 봐야 하는 신호"** 로 확장되어 일상 학습 도구가 된다.

#### 핵심 기술 스택 — AI를 어떻게 활용하는가

**① 게임 진행 흐름 제어 — LangGraph**

> AI의 의사결정 단계를 플로우차트처럼 코드로 그리는 라이브러리. 각 단계(노드)에서 조건에 따라 다음 단계로 분기.

```
[시작] → [사용자 답변 받기] → [LLM이 정답 근접도 채점]
   ├─ 근접도 80+: [정답 공개 + 결과 설명]
   ├─ 근접도 50–80: [살짝 힌트 + 다시 답변 요청]
   └─ 근접도 <50: [더 강한 힌트 + 다시 답변 요청]
```
이 분기를 코드로 명시하면 LLM이 마음대로 답을 누설하지 못한다. 디버깅·재현이 가능.

**② AI 게임 마스터 페르소나 — LangChain Agent (LLM 중립)**

- 시스템 프롬프트: "당신은 회계 학습 게임의 게임 마스터다. 절대 정답을 직접 말하지 마라. 사용자가 스스로 발견하도록 단계적 힌트만 제공하라."
- 사용 가능 도구: `financial.db 조회`, `disclosure.db 조회`, `K-IFRS 조문 검색`, `Beneish M-score 계산`.
- GM은 답을 알지만 도구로 단서만 제공. 백엔드 LLM은 Claude / Gemini / GPT 중 비용·성능에 따라 교체 가능.
- **백엔드 라우팅**: 최종 해설·출처 강제 답변은 품질이 중요하므로 **Bedrock(Claude)**, 매 턴 발생하는 LLM-judge 채점·힌트 초안은 고빈도라 **로컬 GPU 셀프호스팅 모델**로 보낸다(§3.1).

**③ 단계적 힌트 시스템 — InvisiClues 패턴**

> 직접 답이 아니라 점점 구체화되는 단계적 단서를 제공하는 힌트북 방식.

- **Tier 1 (방향)**: "현금흐름표와 손익계산서를 비교해 보세요"
- **Tier 2 (지표)**: "매출채권 회전율을 동종업계와 비교해 보세요"
- **Tier 3 (시점)**: "2013년 4분기와 2014년 2분기 사이를 보세요"
- **Tier 4 (결정타)**: "수익 인식 시점이 작업진행률과 어긋났습니다"

LangGraph가 사용자 답변을 보고 어느 Tier로 갈지 결정.

**④ 사용자 답변 채점 — LLM-as-Judge**

> 한 LLM이 사용자 답변을 평가해 "정답에 얼마나 가까운가 0–100"를 산출.

- 정답 = "작업진행률 조작에 의한 매출 과대 인식"
- 사용자 답변 = "매출채권이 너무 빨리 늘어난 것 같아요"
- LLM-judge: "근접도 65 — 방향은 맞음, 원인을 못 짚음" → Tier 2 힌트 발사

**⑤ Red Flag 패턴 데이터베이스 — CPA 도메인 IP**

> 50–100개의 위험 시그널 패턴을 CPA 4명이 직접 작성. 각 패턴은 (조건 + K-IFRS 조문 + 한국 사례 + 한 줄 설명) 구조.

```python
{
  "id": "RF_001",
  "category": "수익_인식",
  "trigger": "매출 ↑↑ + 매출채권 ↑↑↑ + 영업현금흐름 ↓",
  "kifrs": "1115",
  "korean_case": "대우조선해양 2014",
  "explanation": "매출은 늘었는데 현금이 안 들어오면 인위적 수익 인식 가능성"
}
```

**⑥ 검증 엔진 — 이미 만든 EQS 재활용**

`modules/financial/eqs/`의 기존 모듈을 호출:
- **Beneish M-score** (EQS M2): 이익 조작 확률, 76% 정확도.
- **Modified Jones Model** (EQS M1): 발생액(accruals) 분석.
- **Piotroski F-score** (EQS M5): 9개 재무 건전성 지표.

**⑦ 출처 강제 — Citation-Enforced RAG**

- 모든 힌트 끝에 `[출처: 대우조선해양 2014 사업보고서 p.75 / K-IFRS 1115]`.
- 출처를 못 찾으면 답변 거부 ("이 부분은 정보가 부족합니다").

#### 게임 흐름 + 백엔드 라우팅 (LangGraph state machine)

각 노드가 어느 백엔드로 가는지 한 판 흐름으로 보면(§3.1):

```
[Phase 1: Setup]        정정 전 재무제표·공시 노출 + "수상한 점이 어디일까요?"
[Phase 2: Exploration]  사용자 입력 → LLM-judge 근접도 0–100 산출        → 로컬 GPU (고빈도)
[Phase 3: Tiered Hints] 헤맬 시 Tier 1→4 힌트 초안 생성                 → 로컬 GPU (고빈도)
                        근거 검색(대우조선 보고서 p.75) 임베딩·벡터검색  → 로컬 GPU
[Phase 4: Reveal]       출처 강제 최종 해설(1115 위반·작업진행률)        → Bedrock(Claude) (저빈도·고품질)
                        + K-IFRS 조문 매핑 + Red Flag 카드 → 도감에 추가
                        학습 이벤트 기록(시계열 그래프 엔티티 추출)      → 로컬 GPU (Graphiti)
```

→ 한 판에서 **최종 해설만 Claude(Bedrock)**, 채점·힌트·검색·기록 등 고빈도 단계는 모두 **로컬 GPU**가 처리한다.

#### 시나리오 데이터셋 (3 범주 × 각 5–7건)

**데이터 수집**: 대부분 DART에 공개. CPA 팀이 직접 큐레이션 + 한 줄 학습 포인트 작성.

| 카테고리 | 예시 패턴 | K-IFRS |
|---|---|---|

| 관계자 거래 | 일감 몰아주기, 특수관계자 가격 왜곡 | 1024 |

→ **2주 안에 50–100개 패턴 작성** (CPA 4명 × 2주 × 약 2.5개/일).

### 4.2 도미노 이펙트 — 인과 그래프 동적 생성기 (relation)

#### 핵심 기술 스택 — AI를 어떻게 활용하는가

**① 사업보고서를 지식 그래프로 변환 — GraphRAG**

> 텍스트를 지식 그래프(노드 = 개념·기업·제품, 엣지 = 관계)로 변환한 후 그래프를 탐색해 답변. 일반 RAG보다 다단계 추론 정확도 약 3.4배. LazyGraphRAG로 인덱싱 비용 10–90% 절감.

- 입력: 삼성전자 사업보고서 (200페이지 PDF·HTML)
- 출력: `[삼성전자]--공급-->[LG이노텍]`, `[CAPEX 30조]--영향-->[원익IPS 매출]` 같은 노드·엣지

**② 인과관계 추론 — Causal-LLM (방법론, 별도 모델 아님)**

> Causal-LLM은 새 모델이 아니라 **방법론·프롬프트·알고리즘 패턴**이다. 로컬 LLM을 따로 학습하지 않고, Claude/Gemini API에 추가 설정을 얹는다.
> 1. **Constraint-based causal discovery**(PC algorithm 등 기존 통계 기법)로 후보 인과 그래프 자동 도출
> 2. **인과 추론 프롬프트** — "이 변수 변화의 직접 원인을 단계적으로 추론하라"
> 3. **검증 루프** — LLM 답변을 통계적 테스트로 재검증 → 모순 시 재시도

**단순 LLM 호출과의 차이**
- 단순: "애플 매출 감소 시 LG이노텍 주가 하락한 적 많다" (상관)
- Causal-LLM: "애플 → LG이노텍 카메라 모듈 매출 → 영업이익 → 주가" (검증된 인과 사슬)

GitHub 오픈소스 코드를 한국 공시 도메인에 맞게 변수·프롬프트만 커스터마이즈.

**③ 다단계 전파 — GNN (Graph Neural Network)**

> 노드와 엣지로 이루어진 그래프 구조를 학습하는 신경망. 한 노드의 정보가 엣지를 따라 이웃 노드로 전파되는 패턴을 학습.

- 1차: 애플(직접 영향) → 2차: LG이노텍(1차 공급사) → 3차: 삼성전기(경쟁사 반사이익)
- 처음부터 GNN을 학습하는 대신, **사전학습 LLM이 메시지 전파 패턴을 흉내**(LLM-augmented GNN)하는 방식으로 학습 데이터 부족 문제를 해결.

**④ 그래프 저장소 — networkx → Neo4j** (§3.5 참조)

**⑤ 동적 그래프 시각화 — Cytoscape.js**

> 노드 확장·축소·애니메이션 지원 그래프 시각화 라이브러리. D3.js로 노드가 한 단계씩 펼쳐지는 애니메이션을 추가 제어.

**⑥ 단계별 deep-dive — LangGraph**

사용자가 "왜?"를 클릭하면 한 단계 더 깊은 인과 노드를 동적 생성하는 분기를 코드로 명시.

**백엔드 활용**: GraphRAG 임베딩·KG 추출·GNN 메시지 전파는 **로컬 GPU**에서, Causal-LLM 인과 검증(통계 재검증 후 최종 판단)은 품질이 결정적이라 **Bedrock(Claude)** 으로 보낸다(§3.1).

#### 현재 아키텍처 결합

```
[기존]

modules/disclosure/data/disclosure.db     (이벤트 소스)

[추가]
modules/relation/causal_engine.py         (NEW)
  ├─ disclosure.db에서 이벤트 트리거 추출
  ├─ GraphRAG로 top50 사업보고서 KG 인덱스
  ├─ Causal-LLM으로 인과 노드 5–7개 동적 생성
  └─ 결과 → modules/integration/data/causal_chains/{event_id}.json

[프론트]
modules/integration/dashboard.html
  → Cytoscape.js 인과 레이어 토글
  → 사용자 입력 "애플 -20%" → 노드 확장 애니메이션
  → 각 노드 = 공시 페이지·재무항목·K-IFRS 조문 출처
```

#### 구현 단계

4. Neo4j Aura 마이그레이션 (선택)

### 4.3 새도우 포트폴리오 — Shadow Portfolio Agent (price)

#### 핵심 기술 스택 — AI를 어떻게 활용하는가

**① 페르소나 프롬프트 — AI Hedge Fund 오픈소스 차용**

> Warren Buffett·Charlie Munger·Benjamin Graham 등 투자 거장의 사고방식을 LLM 프롬프트로 구현한 오픈소스. 백테스트 모듈 포함.

- `buffett.py`: "당신은 워런 버핏이다. 시장 변동에 휘둘리지 마라. PBR이 ROE의 절반 이하인지, 경제적 해자가 있는지부터 본다" 같은 시스템 프롬프트.
- 라이선스 확인 후 프롬프트 텍스트만 차용, 구조 코드는 우리 스택에 맞게 재작성.

**백엔드 활용**: 페르소나 추론은 시점 격리·논리 일관성이 결정적이라 **Bedrock(Claude)** 으로 보내고, 누적 패턴 분석·임베딩(InvestorDNA)은 **로컬 GPU**로 처리한다(§3.1).

**② 장기 기억 — Letta (구 MemGPT)**

> LLM 컨텍스트(단기) ↔ 외부 DB(장기)를 OS처럼 자동 swap하는 프레임워크.

- 단기: 현재 시뮬레이션의 사용자 결정·페르소나 응답.
- 장기: 사용자가 지난 30번의 시뮬레이션에서 보인 패턴 (recency bias 32%, herd behavior 18%, ...).
- → InvestorDNA 시각화의 데이터 소스.

**③ 시점 격리 — Zep Graphiti의 Validity Window (핵심 안전장치)**

- 시나리오 시점: 2020-03-15. LLM은 이미 코로나 결과를 학습한 상태 → 그대로 두면 부정 행위.
- Graphiti가 RAG 인덱스에서 2020-03-15 이후 사실을 **자동 차단**.
- 페르소나 시스템 프롬프트: "당신은 2020-03-15 23:59에 멈춰 있다."
- 자동 검증 테스트: 페르소나 답변에 미래 사실 누설 시 fail.

**④ 백테스트 — vectorbt**

> 과거 데이터로 투자 전략을 시뮬레이트해 수익률·샤프 비율·MDD 산출. numpy 벡터화로 빠름.

- 사용자 결정 vs 페르소나 결정 vs 실제 결과 3자 비교 — "버핏 페르소나 +18%, 사용자 -7%, 시장 +3%".

**⑤ 분기 시뮬레이션 — LangGraph Checkpointing**

> 워크플로우 각 단계의 상태를 저장하는 "세이브 포인트".

- 시나리오 진행 중 "다른 선택을 해보고 싶어" → 이전 분기점으로 복귀해 "what-if" 가지치기.

#### 페르소나 3종 (한국 시장 적응)

- **워런 버핏 (가치투자)**: PBR·ROE·moat 중심.
- **퀀트 트레이더**: 팩터 모델·통계·백테스트 결과 인용.
- **모멘텀 투자자**: 추세·상대강도·뉴스 모멘텀.
- (확장) **한국 가치투자 페르소나** — 국내 차별화 포인트.

### 4.4 개인 학습 통합 레이어 — Personal Learning Platform (전체 통합)

#### 핵심 컨셉

3개 응용 기능은 각각 강력하지만, 사용자 입장에서 흩어진 단발성 경험으로 끝나면 학습 효과가 약하다. **모든 활동을 사용자별로 누적·체계화·복습**하는 4번째 레이어가 있어야 비로소 "AI 학습 플랫폼"으로 자리 잡는다.

| 기능 | 저장되는 학습 자취 |
|---|---|
| **도미노** | 탐색한 인과 사슬, 깊이 본 노드, 마주친 K-IFRS 조문, "왜?" 클릭 횟수 |
| **방탈출** | 풀이한 시나리오, 발견한 Red Flag 패턴, 힌트 사용 횟수, 정답 도달 시간 |
| **새도우** | 시나리오 의사결정 이력, 페르소나와 일치/불일치, InvestorDNA 누적 |
| **공통** | 마주친 개념(용어·조문·지표) → **개념 카드 자동 생성** |

#### 핵심 기술 스택 — AI를 어떻게 활용하는가

**① 학습 이벤트 로그 — 이벤트 소싱 패턴**

> 사용자의 모든 행동을 시간순 이벤트로 저장. 현재 상태가 아니라 "어떤 일들이 일어났는지"를 로그로 보관해 사후 어떤 분석도 가능.

```python
LearningEvent(user_id, feature, action, context_json, timestamp)
# ("user_42", "escape", "discover_red_flag", {"pattern": "RF_017"}, ...)
# ("user_42", "domino", "expand_node", {"from": "AAPL", "to": "LGINNOTEK"}, ...)
```

**② 사용자 숙련도 추적 — Bayesian Knowledge Tracing (BKT)**

> 사용자가 한 개념을 "안다/모른다"의 확률을 매 답변마다 갱신하는 교육 AI 기법.

- K-IFRS 1024 = "모름"(50%) → 방탈출에서 관련 Red Flag 발견 → 65% → 도미노에서 조문 인용 노드 클릭 → 75% → 새도우에서 관련 결정 정답 → 85%("마스터").
- 일정 기간 미접촉 → 확률 자동 감소(망각 곡선).
- → "당신이 약한 개념: K-IFRS 1110(35%), 1037(42%)" 식 진단.

**③ 망각 방지 — Spaced Repetition (Anki SM-2 알고리즘)**

> 잊어버리기 직전에 다시 노출하는 학습 기법. 간격(1일 → 3일 → 7일 → 21일 → 60일)으로 복습 제안.

- "RF_017: 매출채권 회전율 급락" 패턴을 처음 발견 → 다음날 비슷한 미니퀴즈 제안.
- 정답 시 다음 노출 간격 ↑, 오답 시 ↓. 매일 dashboard 접속 시 "오늘의 복습 카드 3장" 알림.

**④ 개념 카드 자동 생성 — LLM 기반 요약**

- 앞면: 개념명 + 핵심 한 줄 ("K-IFRS 1024: 특수관계자 거래 공시 의무").
- 뒷면: 자세한 설명 + 언제 어디서 마주쳤는지 ("2026-05-12 방탈출 대우조선 시나리오에서 발견").
- 모든 카드는 출처 강제(Citation-Enforced RAG 재활용), 검색·즐겨찾기 가능.

**⑤ 주간 학습 리포트 — LLM 요약 + 시각화**

> 매주 일요일 자동 생성. 그 주의 학습 이벤트 로그를 LLM이 한 페이지 리포트로 요약.

- 이번 주 활동 / 새로 배운 개념 / 강점 변화 / 약점 진단 / 다음 주 추천 학습 경로 3가지.

**백엔드 활용**: 개념 카드·주간 리포트의 LLM 요약은 정형화된 대량 작업이라 **로컬 GPU 셀프호스팅 모델**로 처리한다(어려운 진단만 선택적으로 Bedrock)(§3.1).

**⑥ 학습 우주 시각화 — D3.js Personal Galaxy**

> 학습 이력을 별자리로 시각화. 각 별 = 마주친 개념, 별 사이 연결 = 학습 경로.

- 마스터한 개념 = 밝은 별, 약한 개념 = 흐린 별, 미접촉 = 어두운 영역.
- 별 클릭 → 개념 카드 + 처음 마주친 시나리오로 이동.

#### 현재 아키텍처 결합


## 9. GPU·Disk 자원 운영 계획

본 프로젝트는 **A100 GPU 1장 + Disk 200GB** 구성으로 운영한다. 두 자원의 개념과, 이 규모로 충분한 근거·운영 방안을 정리한다. (로컬 GPU ↔ Bedrock 백엔드 라우팅 원칙과 GPU 활용 3단계는 §3.1 참조)

### 9.1 GPU (A100 1장) — 대규모 학습 없이 추론·경량 학습 중심

"학습"은 세 단계로 나뉘며, 본 프로젝트는 **대규모 사전학습을 하지 않고** 추론을 중심으로, 최대치가 경량 파인튜닝이다.

| 단계 | 의미 | 필요 자원 | 본 프로젝트 |
|---|---|---|---|
| **사전학습 (pretraining)** | 모델을 0에서 구축 | GPU 수백~수천 장, 수주~수개월 | 해당 없음 |
| **파인튜닝 (QLoRA)** | 완성된 모델에 도메인 데이터를 경량 학습 | A100 1장, 수시간~1일 | 최대치 (선택) |
| **추론 (inference)** | 완성된 모델을 실행 | A100 1장 | 작업 대부분 |

**plan 내 "학습"의 실제 성격** — 어느 것도 대규모 학습이 아니다:
- **Causal-LLM (도미노)**: 별도 모델 학습 없이 통계 알고리즘 + 프롬프트만 얹음 → 학습 아님
- **GNN (도미노)**: LLM-augmented 방식으로 학습을 회피. 직접 학습해도 노드 2,600개 소규모 그래프 → 단일 GPU로 수십 분
- **BKT (학습 레이어)**: 베이즈 확률 갱신, GPU 미사용(CPU)
- **RAG·임베딩·셀프호스팅 LLM**: 완성 모델 실행 = 추론
- **QLoRA 도메인 파인튜닝 (§3.1 ③, 선택)**: 7~13B 모델의 어댑터만 조정 → A100 1장 수시간. 우리가 하는 유일한 "학습"이자 최대치

→ **대규모 학습이 없으므로 A100 1장으로 추론·임베딩·소규모 GNN·(선택)QLoRA가 모두 가능하다.**

**단일 GPU 운영 원칙** (용량이 아닌 스케줄의 문제):
- GPU 1장은 **무거운 작업 2개를 동시에 처리하지 못한다** — 예: 파인튜닝 중에는 같은 GPU로 라이브 서빙이 불가.
- → **시간 분리**: 파인튜닝·대량 인덱싱은 데모·테스트가 없는 시간대에 배치하고, 완료된 모델로 서빙한다.
- VRAM이 클수록(80GB급) 셀프호스팅 모델과 임베딩 모델을 동시에 올릴 여유가 커진다.

### 9.2 Disk (200GB) — 사용량 구성과 관리 원칙

본선·결선에서 셀프호스팅 + QLoRA + 2,600개 인덱싱을 모두 켰을 때의 사용량 구성:

| 항목 | 대략 |
|---|---|
| CUDA·PyTorch 등 실행 환경 | 30–50GB |
| 셀프호스팅 모델(4-bit) + 파인튜닝본 | 15–40GB |
| 임베딩·리랭커 모델 + 2,600 벡터DB | 15–25GB |
| 공시 corpus(텍스트) + 파인튜닝 데이터·체크포인트 | 20–40GB |
| 작업·다운로드 버퍼 | 20–30GB |
| **합계 (피크)** | **약 120–185GB** |

→ 계획 범위(자체 LLM 호스팅 + 파인튜닝 + 2,600 인덱싱)에서 **200GB로 여유 있게 수용**된다.

**200GB 안에서 유지하는 3원칙:**
1. **모델은 양자화본(4-bit)으로 보관** — 대형 모델을 fp16으로 받으면 용량이 수 배로 늘어난다. 4-bit면 같은 모델을 대폭 줄여 보관.
2. **원본 PDF·HTML은 디스크에 쌓지 않는다** — 2,600개 사업보고서 원본을 모두 저장하면 수십 GB. **텍스트·벡터만 남기고** 원본은 필요 시 다시 수집한다(클라우드로 들어오는 인바운드 데이터는 부담이 적다).
3. **모델 다운로드 캐시를 주기적으로 정리** — 캐시가 누적되며 공간을 잠식하므로 정기 정리.

Disk는 단계적으로 늘릴 수 있는 자원이므로, 계획 범위는 200GB로 운영하고 특정 실험이 이를 초과할 때만 상향한다.
