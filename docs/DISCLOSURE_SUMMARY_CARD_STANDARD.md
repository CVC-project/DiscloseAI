# 사업보고서 요약카드 표준

작성일: 2026-08-01

이 문서는 `CompanySummary`와 사업보고서 reader 화면이 따라야 할 요약카드 구조와 품질 기준을 고정한다. 목적은 HTML 스크린샷을 보고 다시 만드는 방식이 아니라, 데이터와 UI가 같은 기준을 공유하게 만드는 것이다.

## 1. 화면 역할

사업보고서 요약카드는 초보 투자자가 "이 회사가 무엇으로 돈을 버는지"를 먼저 이해하게 만드는 영역이다.

재무제표 수치, EQS 점수, 현금흐름 상세 분석은 별도 탭에서 다룬다. 사업보고서 요약카드는 사업보고서 `II. 사업의 내용`을 중심으로 회사의 사업 구조, 제품·서비스, 최근 변화, 업종별 핵심 변수를 쉬운 말로 압축한다.

## 2. 데이터 소스

기본 소스는 로컬에 수집된 DART 사업보고서 파싱 결과다.

- 원문 파싱: `modules/disclosure/data/fulltext/<corp_code>/<rcept_no>/parsed.json`
- 요약 JSON: `modules/disclosure/data/fulltext/<corp_code>/<rcept_no>/summary.json`
- SQLite 테이블: `modules/disclosure/data/disclosure.db` 의 `company_summary`
- 모델 정의: `modules/disclosure/models.py` 의 `CompanySummary`

외부 기사, 블로그, 증권사 리포트 내용은 기본 요약 근거로 섞지 않는다. 이미지 자산은 시각화를 위한 보조자료이며, 사업내용 문장은 DART 사업보고서 기반으로 작성한다.

## 3. 요약카드 구조

### 3-1. 행성 주변 사업·제품 카드

역할: 회사가 실제로 파는 제품·서비스를 시각적으로 보여준다.

데이터:

- `business_cards[].title`
- `business_cards[].caption`
- `business_cards[].image`
- `business_cards[].image_source`
- `summary.products`
- `summary.segments`

규칙:

- 카드 수는 회사별 2~4개를 기본으로 한다.
- 제품·서비스가 3개면 빈 자리를 만들지 않고 3개만 배치한다.
- 지주사·금융지주는 "자본정책", "운용자산" 같은 추상 개념을 사업 카드로 쓰지 않는다. 실제 자회사·서비스 축을 쓴다.
- 한 카드 안에서는 제품명을 나열하기보다 그 제품이 어떤 매출 축인지 설명한다.

예시:

- 삼성전자: DX, DS, SDC, Harman
- SK하이닉스: DRAM, NAND Flash, HBM, CIS/응용제품
- KB금융: KB국민은행, KB증권, KB손해보험, KB국민카드
- 조선사: 상선, 해양플랜트, 특수선, 엔진/기자재

### 3-2. DART II 사업내용 요약

역할: 사업보고서의 사업개요와 사업현황을 읽고, 회사가 하는 일을 한눈에 설명한다.

기본 구성:

1. 요약 한눈에
2. 부문별 매출비중과 사업 설명
3. 우리가 읽고 요약한 사업보고서 핵심

중복 방지:

- `요약 한눈에`은 제품 목록 반복을 최소화한다.
- `부문별 매출비중`은 사업부문 구조와 비중만 다룬다.
- `우리가 읽고 요약한 사업보고서 핵심`은 제품명이 아니라 사업보고서가 말하는 변화, 리스크, 성장 축, 수요 환경을 설명한다.

### 3-3. 회사별 직접 요약 카드

역할: 사업보고서에서 회사 이해에 필요한 핵심 문장을 고르고, 초보 투자자가 바로 이해할 수 있게 문단으로 풀어쓴다.

권장 구조:

- `1. 사업보고서에서 확인된 변화`
- `2. 투자자가 확인해야 할 포인트`

카드 하나의 구성:

- 제목: 12자 안팎의 명사형 또는 짧은 문장
- 핵심값: 1줄. 예: `DS 부문 영업이익 24.9조원`
- 설명문: 1~2문장

금지:

- "사업보고서를 확인하세요", "원문을 봐야 합니다" 같은 안내형 문장
- 제품명·사업부문 목록의 반복
- 사업보고서 원문 복붙
- "확인할 필요가 있습니다"만 반복하는 체크리스트형 문장
- 문장이 중간에 끊긴 상태

## 4. 업종별 맞춤 포인트

요약카드는 업종별로 같은 질문을 던지면 안 된다. 회사 성격에 따라 아래 우선순위를 적용한다.

### 제조업·장치산업

추천 포인트:

- 원재료 가격 변화
- 생산능력·가동률
- 설비투자와 고정비 부담
- 제품 믹스 변화
- 수주잔고와 납기

쉬운 설명 기준:

- 가동률: 공장이 실제로 얼마나 꽉 차서 돌아갔는지
- 원재료 가격: 제품을 만드는 비용이 얼마나 변했는지
- 제품 믹스: 이익률이 높은 제품 비중이 얼마나 커졌는지

### 금융업

추천 포인트:

- 은행·증권·보험·카드 등 수익원 분산
- 순이자이익과 수수료 수익
- 대손충당금과 연체 관리
- 보험 손해율 또는 운용손익
- 배당과 자본 여력

금지:

- 제조업식 가동률, 원재료 가격, 공장 설비투자를 핵심 포인트로 쓰지 않는다.

### 지주사

추천 포인트:

- 핵심 자회사 구성
- 투자 포트폴리오 변화
- 배당 수입과 지분가치
- 신사업 편입·매각

금지:

- 지주사 자체를 제조사처럼 설명하지 않는다.

### 바이오·제약

추천 포인트:

- 현재 매출 제품과 개발 파이프라인의 분리
- CDMO·위탁생산 여부
- 품목허가, 임상, 기술이전
- 개발비 부담과 손상 가능성

쉬운 설명 기준:

- CDMO: 다른 회사의 바이오의약품을 대신 개발·생산해주는 사업
- 바이오시밀러: 특허가 끝난 바이오의약품과 비슷하게 만든 의약품

### 플랫폼·게임·콘텐츠

추천 포인트:

- 이용자 기반이 광고·결제·구독·아이템 매출로 이어지는 구조
- 신작 출시와 기존 IP 활용
- 해외 매출 비중
- 수수료율과 거래액

금지:

- 앱 이름 일부가 다른 용어와 겹친다고 잘못 주석을 붙이지 않는다. 예: `TMAP`에 `AP` 주석 금지.

### 건설·조선·방산

추천 포인트:

- 수주잔고
- 선종·프로젝트 믹스
- 납기와 원가 상승
- 장기계약 구조
- 방산 수출과 후속 정비·부품 수요

금지:

- 초보 투자자용 카드에서 공정률 산식을 길게 설명하지 않는다.

## 5. 문장 품질 기준

### 길이

- `products`: 3~12개 권장
- `segments`: 1~6개 권장
- `segment.desc`: 45자 이하 권장
- `investor_notes`: 120~650자 권장
- 직접 요약 카드 설명문: 카드당 1~2문장

### 톤

- 문장은 평서문으로 끝낸다.
- 한 문장 안에 너무 많은 개념을 넣지 않는다.
- "연결됩니다", "판매됩니다"처럼 주어가 어색한 수동형을 피한다.
- "확인해야 합니다"는 남발하지 않고, 실제 요약을 먼저 제공한다.

### 쉬운 용어 주석

초보 투자자가 모를 가능성이 높은 용어는 첫 등장에만 주석을 붙인다.

예시:

- DRAM: 데이터를 임시로 저장해 컴퓨터·서버가 빠르게 일하게 돕는 메모리
- NAND Flash: 전원이 꺼져도 데이터를 보관하는 저장용 메모리
- HBM: AI 서버에 쓰이는 고성능 메모리
- 모바일AP: 스마트폰의 두뇌 역할을 하는 칩
- Foundry: 다른 회사가 설계한 반도체를 대신 생산하는 사업
- OLED: 스스로 빛을 내는 디스플레이 패널
- 충당금: 앞으로 생길 손실에 대비해 미리 비용으로 잡아두는 돈
- 손해율: 받은 보험료 대비 보험금이 얼마나 나갔는지 보는 비율

동일 화면에서 같은 용어가 여러 번 나오면 첫 등장에만 설명한다.

## 6. 품질검사 기준

품질검사는 `scripts/audit_disclosure_summary_quality.py`로 수행한다.

필수 통과 기준:

- `summary.json` 누락 0건
- 제품 빈값 0건
- 사업부문 빈값 0건
- 투자자용 요약 빈값 0건
- 자동 로컬 파서 요약의 명백한 오류 0건
- 문장 끊김 후보는 수동 검토 대상으로 분리

검사 대상:

- 표 머리글이 제품명으로 들어간 경우
- 재무제표 계정이 사업부문으로 들어간 경우
- 차입금·금융자산·감가상각 등 비사업 항목이 제품/사업으로 들어간 경우
- `사업보고서를 확인하세요`처럼 요약이 아니라 안내만 하는 문장
- 너무 긴 문장 또는 문장 중간 끊김

## 7. 구현 원칙

- 데이터 구조는 기존 `CompanySummary`를 유지한다.
- 화면은 `products`, `segments`, `investor_notes`, `glossary_terms`, `business_cards`를 조합해 렌더링한다.
- 전체 상장사 확장 시에도 먼저 로컬 `summary.json`과 DB를 만들고, 그 다음 UI용 JSON을 생성한다.
- 자동 파서가 애매하게 뽑은 회사는 `OVERRIDES` 또는 별도 수동 요약 후보로 분리한다.
- HTML에 직접 데이터를 손으로 붙이지 않고, 생성 스크립트와 기준 문서를 함께 유지한다.

## 8. 복합기업 대표 부문 정규화

사업부문이 7개 이상인 회사는 화면에서 그대로 나열하면 초보 투자자가 구조를 읽기 어렵다. 이 경우 원자료를 삭제하는 것이 아니라, 화면 표시용으로 가까운 사업을 묶어 대표 부문 3~6개로 정규화한다.

정규화 스크립트:

```bash
python scripts/normalize_summary_card_contract.py
python scripts/audit_disclosure_summary_quality.py
```

정규화 원칙:

- 매출 비중이 큰 부문을 우선 남긴다.
- 같은 경제적 성격의 소부문은 묶는다. 예: 마트+슈퍼, 화학+윤활유, 책상+수납
- 금융업은 은행·증권·보험·카드처럼 투자자가 이해하기 쉬운 수익원 단위로 묶는다.
- 지주사·복합기업은 자회사 이름 나열보다 사업 성격으로 묶는다.
- 제품/사업 카드와 중복되는 세부 제품명은 줄이고, 부문 설명은 70자 안쪽으로 유지한다.

## 9. 업종별 자동 요약 생성 기준

`scripts/auto_fill_missing_disclosure_summaries.py`의 자동 생성분은 모든 회사를 같은 문장 틀에 넣지 않는다. 먼저 사업보고서 II. 사업의 내용 원문, 제품 후보, 사업부문 후보를 바탕으로 회사 성격을 금융, 지주, 바이오, 플랫폼, 수주형, 제조, 일반 렌즈 중 하나로 분류한다.

렌즈별 요약 첫 문장은 회사별 제품·서비스를 설명형으로 시작한다. 제조업은 "주요 제품·서비스는 ...입니다", 수주형 사업은 "주요 사업은 ...입니다. 계약을 따낸 뒤 제작·공사·납품을 거쳐 매출을 만듭니다"처럼 쓴다.

오분류를 줄이기 위해 제품·사업부문 표에 우연히 등장한 단어만으로 금융업이나 바이오로 분류하지 않는다. 금융업은 회사명 또는 원문에 은행업·보험업·증권업·카드업·여신전문·금융지주 등 명확한 표현이 있을 때 우선 적용한다. 바이오는 회사명에 바이오·제약이 있거나 원문에서 관련 표현이 충분히 반복될 때 적용한다.

자동 생성 시 제외하는 원문 조각:

- `구분`, `상품`, `제품명`, `모델명`, `매입유형`, `내수`, `수출` 같은 표 머리글
- `판매경로`, `수주현황`, `생산능력 및 생산실적`, `원재료 매입 현황` 같은 목차성 문구
- 괄호가 닫히지 않은 문장, 표 주석 표식, URL, 전자공시시스템 안내 문구
- "사업보고서를 확인하세요"처럼 요약이 아니라 안내만 하는 문장
